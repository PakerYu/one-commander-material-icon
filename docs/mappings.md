# Mapping tables

`mappings/file-icons.tsv` and `mappings/folder-icons.tsv` are **generated** by
`scripts/build.py` and committed so that every change is reviewable. They are checked into
git on purpose: the filename *is* the mapping key for One Commander.

## `file-icons.tsv`

```
material_icon	onecommander_file	extensions
python	python.png	py,pyw
javascript	js.png	js,mjs,cjs
```

| Column | Meaning |
| --- | --- |
| `material_icon` | icon name in the upstream project (`icons/python.svg`) |
| `onecommander_file` | the file name One Commander matches, i.e. `','.join(tokens) + '.png'` |
| `extensions` | the tokens covered by that file (same list as the file name) |

Rules the generator applies:

1. **Dot-files first.** `.npmrc` becomes the token `npmrc` and is claimed before extension
   rules, so `npm` wins it over `settings`.
2. **Definition order.** Remaining extensions are claimed in the order they appear in the
   upstream `fileIcons.ts`; first claim wins (`tsx` belongs to `react_ts`, not `qwik`).
3. **ASCII, single segment.** Tokens that cannot be part of a file name, or that are not
   ASCII, are dropped (`no-usable-token` in the manifest).
4. **100 characters.** When the joined list exceeds the limit, the tokens are chunked and
   every chunk is rendered as its own PNG with identical content.
5. **Windows reserved names.** `con`, `prn`, `aux`, `nul`, `com1…9`, `lpt1…9` can never be a
   file name and are skipped.

## `folder-icons.tsv`

```
material_icon	folder_name	onecommander_file
folder-src	src	src.png
folder-vuex-store	stores	stores.png
```

| Column | Meaning |
| --- | --- |
| `material_icon` | upstream folder icon (`folder-src`) |
| `folder_name` | the folder name One Commander compares against |
| `onecommander_file` | the PNG file name (`<folder_name>.png`) |

Claiming order:

1. The icon whose name equals `folder-<name>` claims `<name>` first
   (`folder-store` → `store`).
2. Remaining aliases are claimed in definition order
   (`folder-vuex-store` → `stores`, `folder-redux-reducer` → `reducers`).

This mirrors the upstream folder themes and keeps the result deterministic across runs.

## Drift detection

`make check` re-reads the vendored definitions, regenerates both tables in memory and
compares them with the committed files, then verifies every row points at an existing PNG of
the expected size. It writes nothing, so it is safe in CI:

```
file icons: mapping matches the source (403 rows)
file icons: all PNGs present with the expected size (403)
folder icons: mapping matches the source (925 rows)
folder icons: all PNGs present with the expected size (925)
main folder icon: present with the expected size (64x64)
```

Any difference is printed as `+`/`-` rows and makes the command exit non-zero.

The `MainFolderIcon` is not a mapping: it is one PNG rendered from the upstream default
`icons/folder.svg` (`pack/MainFolderIcon/<pack-name>.png`, 64×64). `make check` verifies that
both the source SVG and the output PNG exist.

## Manifest

`dist/pack.json` (generated by `make build`, not committed because it carries a timestamp)
records the upstream version, renderer, size, counts and the reason for every skipped icon.
It also has a `mainFolderIcon` block (`file`, `size`, `source`) and
`counts.mainFolderPngs`. `scripts/verify.py` uses it to cross-check the PNG counts on disk.
