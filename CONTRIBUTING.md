# Contributing

Thanks for helping. Most contributions are either a **mapping change** or a **rebuild with a
newer upstream**.

## Requirements

- Python 3.10+ (the build script is standard library only)
- Inkscape 1.x for rendering — optional, `--renderer copy` and `--renderer imagemagick`
  work too
- PowerShell 7+ (only for the Windows installers)
- `zip` (only for `make dist`)

```bash
make check     # mapping drift: mappings/ vs pack/ vs vendor/
make build     # full re-render into pack/
make verify    # artifact validation
```

## Mapping changes

`mappings/*.tsv` are generated by `scripts/build.py`, so edit the **source of truth** — the
vendored TypeScript definitions or the rules in `scripts/build.py` — then re-run `make build`.
Hand-editing the TSVs will be overwritten on the next build.

- Extension / folder-name associations: `vendor/material-icon-theme/src/core/icons/*.ts`
- Filename flattening, 100-character splitting and reserved-name handling:
  `scripts/build.py` (`build_file_mapping`, `build_folder_mapping`)
- Skipped icons: reported in `dist/pack.json` under `skipped`

If you only want to change *what* an icon is called for a given Material icon, look for the
`folder-*` prefix and extension handling rules before touching the tables.

## Rebuilding for a new upstream release

1. Bump `tag` and `version` in `upstream.lock.json`.
2. `make vendor` — refresh `vendor/material-icon-theme/`.
3. `make check` — review the mapping diff (`git diff mappings/`).
4. `make build verify dist`.
5. Update `CHANGELOG.md` and commit the regenerated `pack/` together with the mappings.

Rendering is not byte-stable across Inkscape versions: expect binary diffs in `pack/` when
the renderer changes. `make check` only compares names, sizes and mapping rows.

## Pull requests

- Keep the diff focused; do not reformat unrelated code or re-render icons that did not change.
- `make check verify` must pass; CI runs the same commands.
- Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:` …).
- Mention the upstream version you built against.

## Code comments

`scripts/build.py` keeps its inline comments and internal docstrings in Chinese (the original
author's language); user-facing CLI output is English. New code should use English comments
where it makes sense.
